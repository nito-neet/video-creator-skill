# asset-capture.md — サイトから実物を切り出す

動画に「そのサービスらしさ」を入れる一番確実な方法は、**実物の画面をそのまま見せる**こと。
ここは地雷が多いので、着手前に全部読む。

---

## 0. 大前提：ダークモードで撮る

**背景が暗い動画に、ライトモードの切り抜きを載せると、白い板として浮いて全カットが破綻する。**

サイトにダークモードがあるなら必ず切り替えてから撮る。
ダークモードの背景色が動画の背景色と同じなら、**枠なしで画面に溶ける**。

ASTER の場合、ダークモードの背景が `#002d3d` で、動画の背景色と完全に一致した。
これが v2 がうまくいった最大の理由。

下見（`site-explore.mjs`）の `report.json` の `darkToggle` に、切り替えボタンの aria-label が入っている。
それを `capture.config.mjs` の `darkToggle` にそのまま書く。

ダークモードが無いサイトなら、**動画の背景色をサイトの明るい配色に寄せる**（逆に合わせる）。

---

## 1. 手順

```bash
# 1. 下見（質問を出す前にやる）
node scripts/site-explore.mjs https://example.com

# 2. report.json とスクリーンショットを見て capture.config.mjs を書く

# 3. 撮る
node scripts/capture-site.mjs

# 4. 目録を作り直す（撮り直したら毎回）
node scripts/gen-assets.mjs

# 5. 撮ったものを一覧にして目で見る
```

---

## 2. 何を撮るか

動画のカットの型に合わせて、名前は**用途で付ける**（サイト側の呼び名に引きずられない）。

| 名前 | 何を撮るか | どのカットで使うか |
|---|---|---|
| `home` | サービスの全景（トップ画面まるごと） | C6（画面が奥から迫る） |
| `proof-a/b/c` | ベネフィットの根拠になっている場所 | C8–C10（言葉＋裏づけ） |
| `stage-1..4` | 段階・章・フェーズの見出し | C11（積層） |
| `widget` | 進捗・現在地・状態を表す小さな部品 | C13（現在地） |
| `logo-mark.png` | ロゴマーク（透過） | C5・CTA |
| `thumbs/*` | カード・サムネの類を全点 | C7（数字と同期して埋まる） |

**ベネフィットの根拠は、コピーを書く前に探す。** 根拠が見つからない言葉は動画に出さない。

---

## 3. 切り出しの3つの型

### `type: 'viewport'` 画面まるごと

一番確実。全景を見せるカットはこれ。

### `type: 'clip'` 座標指定

`{x, y, width, height}` を CSS ピクセルで指定する。**狙った範囲を確実に取れる。**
スクリーンショットを見て座標を読み取ればいいので、実はこれが一番速い。

### `type: 'text'` 文字を手がかりに探す

文字を含む要素から親をたどり、`maxW` / `maxH` に収まる最大の祖先を撮る。

**親をたどりすぎて画面全体（1440×900）を掴む事故が何度も起きた。**
必ず `maxW` / `maxH` を指定する。指定しないと body まで行く。

見えない `<script>` の中の JSON に同じ文字が入っていて、そちらを掴む事故もあった（→ lessons.md B-7）。
テンプレートの `capture-site.mjs` は「見えている要素」だけに絞ってあるので、そのまま使えば大丈夫。

### 画面の下にあるものは `scrollTo` を足す

ページ下部のセクションは、そのままでは画面外にいて撮れない。
`scrollTo` に目印の文字を書くと、撮る直前にそこまでスクロールする。

```js
{name: 'proof-c', type: 'clip', scrollTo: 'バイブコーディング', clip: {x: 262, y: 60, width: 1178, height: 300}}
```

`type: 'text'` は、測った位置が画面外だったら自動でスクロールしてから測り直すので、指定は不要。

## 4. いちばんやりがちな失敗：横長すぎて字が読めない

サイトの見出しは幅 1160px でも、**文字は左の 400px にしか無い**ことが多い。
そのまま撮ると、動画に載せたとき文字が 1/3 の大きさになって読めない。

**対処：`width` を足して、文字のある範囲だけに詰める。**

```js
// ✗ 幅 1160px で撮る → 動画上で文字が読めない
{name: 'stage-1', type: 'text', text: '第1段階の見出し', maxW: 1200, maxH: 200}

// ○ 520px に詰める → 実質2倍の大きさになって読める
{name: 'stage-1', type: 'text', text: '第1段階の見出し', maxW: 1200, maxH: 200, width: 520, pad: 10}
```

**目安：切り抜きの横幅が 600px を超えたら、詰められないか疑う。**

撮ったら必ず一覧にして、**動画に載る大きさで文字が読めるか**を確かめる。
読めないなら `width` を詰めて撮り直す。ASTER では2箇所で撮り直した。

## 5. ロゴは CSS の背景画像になっていることが多い

`<img>` でも `<svg>` でもなく、`<span style="background-image:url(...)">` で表示されているケース。
要素をスクリーンショットしても 30px の小さい画像しか取れない。

**対処：**

1. 下見の `report.json` の `bgImages` を見る
2. そこに `/brand/logo-mark-96.webp` のような URL があれば、**サイズ指定を外した元ファイルを試す**

```bash
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" "https://example.com/brand/logo-mark.png"
```

ASTER では `logo-mark-96.webp`（7KB）から `logo-mark.png`（1024×1024・透過・141KB）にたどり着けた。

`capture.config.mjs` の `download` に書けば落とせる。

```js
download: [{url: '/brand/logo-mark.png', as: 'logo-mark.png'}],
```

### 透過で撮りたいとき

要素のスクリーンショットで透過にするには、ページの背景を消してから撮る。

```js
await page.addStyleTag({content: '*{background-color:transparent !important}'});
await el.screenshot({path: '...', omitBackground: true});
```

`capture.config.mjs` のページに `transparent: true` を付けると同じことをする。
ただし**元ファイルが取れるならそちらが常に上**（解像度が違う）。

## 6. 遅延読み込みでサムネが空になる

ページ下部の画像は、スクロールするまで読み込まれない。
そのまま `img` を集めると、下の方が空 URL になる。

**対処：撮る前に一度下までスクロールする。** `capture-site.mjs` の `wakeLazyImages()` がやっている。

## 7. サムネの並び順を記録する

グリッドが埋まるとき、**並び順が色の移り変わりを決める**。
サイト上の並び（＝カテゴリ順）のまま使うと、埋まるにつれて色味が自然に移る。

`capture-site.mjs` の `thumbs` 設定が `materials/thumb-order.json` に DOM 順で記録し、
`gen-assets.mjs` がその順で `THUMBS` を並べる。

**サムネの点数は、動画で見せる数字と必ず一致させる。**
ズレていたら `timeline.ts` が起動時に例外で落ちるので気づける。

## 8. 撮った後の確認

必ず一覧画像にして、自分の目で見る。

```bash
# 個別に縮小してから xstack で並べる（tile は連番以外で詰まる）
ffmpeg -y -v error -i a.png -i b.png -i c.png \
  -filter_complex "[0][1][2]xstack=inputs=3:layout=0_0|w0_0|w0+w1_0[v]" \
  -map "[v]" -frames:v 1 materials/preview/sheet.png
```

見るポイント：

1. **ダークモードで撮れているか**（背景が明るいものが混じっていないか）
2. **文字が読める大きさか**（読めないなら詰めて撮り直す）
3. **狙った範囲が入っているか**（親をたどりすぎて全画面になっていないか）
4. **上下に別の要素が食い込んでいないか**（`offsetY` で開始位置をずらす）
5. **ロゴに透過があるか**（`ffprobe` の `pix_fmt=rgba` で確認）

## 9. 権利の確認

- **依頼主自身のサイトなら、ロゴも画面もサムネも自由に使ってよい。**
- 他社のサイトから撮るのは原則やらない。必要なら依頼主に許諾を確認してもらう。
- 画面の切り抜きに**他社の製品名が写り込む**ことがある（連携先・講座名など）。
  依頼主が自分の表示として掲げているものをそのまま写す分には問題ないが、
  **動画側のテキストとして他社名を読ませる演出は入れない。**報告に一言書く。
- 個人情報・実在の顧客名・メールアドレスが写り込んでいないか、撮った画像を必ず確認する。
