# lessons.md — 実際に踏んだ地雷と対処

ASTER（https://aster.nito1.com/）の15秒動画を v1・v2 と2本作ったときに、
**実際に起きた事故**だけを書いてある。想像で書いたルールは入れていない。
実装に入る前に必ず読む。

---

## A. 見た目の事故（毎回起きる）

### A-1 文字が画面の端で切れる ── いちばん起きる

v1 では 5 箇所で起きた。「明日、使える。」「作れるようになる。」「まず、現在地から。」が
縦画面の左端で切れていた。原因は**カットごとに文字サイズを手打ちしていた**こと。

**対処：`src/motion/fit.ts` の `fitSize()` を全カットで必ず通す。**

```ts
// ✗ 手打ち
fontSize: 158 * s

// ○ 文字数から必要幅を見積もって、入らなければ自動で縮める
fontSize: fitSize(text, 158 * s, width - padX * 2)
```

叩きつけ（scale が 1 を超える）カットは `fitSizeScaled()` を使い、**山の倍率まで含めて**収める。

```ts
const PEAK = 1.35;
const size = fitSizeScaled(text, 200 * s, safe, PEAK);
const scale = slam(f, 0, land, PEAK);
```

`fitSize()` には 4% の内側余白が入っている。これが無いと端に張り付いて切れて見える。

### A-2 0 秒目が切れていた ── サムネが破綻する

v1 の C1 は「AI、勉強した。」1行で、叩きつけの山を 1.8 倍にしていた。
**f0（＝ SNS のサムネになるフレーム）で左右が切れた。**

**対処：**
- 先頭カットの山は **1.3〜1.4 倍まで**に下げる
- 1行が長いなら **補足＋主役の2行に割る**（階層差も付いて一石二鳥）

```
✗ 「AI、勉強した。」1行 / 山 1.8倍
○ 「AI、」（補足）＋「勉強した。」（主役）2行 / 山 1.35倍
```

### A-3 横（16:9）で文字が小さく浮く ── 直感と逆

「縦が基準だから横は縮める」と考えて `s = 0.72` にしたら、横の文字が画面の中で小さく浮いた。
**横は幅に 1.8 倍の余裕がある。縮めるのではなく拡大するのが正しい。**

```ts
// ✗ s: vertical ? 1 : 0.72
// ○ s: vertical ? 1 : 1.4
```

入り切らない分は `fitSize()` が縮めるので、係数は強気でよい。

### A-4 横で左右に並べると必ずはみ出す

横のカットで「文字｜画面の切り抜き」を左右に置いたら、文字が左端で切れた。
文字サイズを**画面の全幅**で計算していたのが原因。

**対処：左右に並べるカットでは、文字に使える幅は安全域の 44% として計算する。**

```ts
const textBox = vertical ? width - padX * 2 : (width - padX * 2) * 0.44;
const size = fitSize(text, desired, textBox);
```

同じ理由で、縦に積むカット（見出し＋4段のパネルなど）は**横だと高さが足りなくなる**。
横では行の幅を安全域の 46% くらいに絞って、高さを半分にする。

### A-5 0.5 秒カットの先頭フレームが空になる

15フレームのカットで、マスクやフェードを `f=0` から始めると、先頭の1〜2フレームが真っ黒になる。
コンタクトシートで「空のコマ」として並ぶので気づける。

**対処：開始を 2〜4 フレーム前倒しする。**

```ts
// ✗ wipe(f, 0, 7, 'up')      → f=0 で 0% 開いている
// ○ wipe(f, -2, 7, 'up')     → f=0 で既に 28% 開いている
// ✗ opacity: fade(f, 0, 5)
// ○ opacity: fade(f, -2, 5)
```

### A-6 構図を変えたつもりが全部同じに見える

ベネフィット3連を「左寄せ／右寄せ／中央」で作ったのに、3つとも見た目が同じだった。
`fitSize()` が3つとも安全域いっぱいのサイズを返すので、**寄せの差が消えていた。**

**対処：寄せだけでなく、置く高さと大きさでも差を付ける。**

```ts
const LAYOUT = [
  {size: 150, align: 'flex-start', textY: 0.24},  // 上・左・中
  {size: 128, align: 'flex-end',   textY: 0.52},  // 下・右・小
  {size: 205, align: 'center',     textY: 0.21},  // 中・中央・最大（着地点）
];
```

### A-7 残像が消えずに二重像になる

高速スライドの残像を `opacity` 固定で置いたら、スライドが終わった後も残って
「ぼやけた二重像」として残り続けた。

**対処：着地後 4 フレームで残像を 0 にする。**

```ts
const trail = interpolate(f, [3, 7], [1, 0], clamp);
// 残像の opacity に trail を掛ける
```

### A-8 字間を開く演出でサイズ計算を間違える

「散らばった文字が字間を閉じて収束する」演出で、
**開いた状態の幅を引いてから文字サイズを決めた**ら、文字が極端に小さくなった。

```ts
// ✗ 開き幅を引いてからサイズを決める → 51px になった
const size = fitSize(word, 200, safe - openPx * word.length);

// ○ サイズは「閉じた状態」で決め、開き幅の方を画面に収まる値にする
const size = fitSize(word, 210 * s, safe);
const w = size * 0.62 * word.length;
const openPx = Math.max(0, (safe - w) / (word.length - 1));
```

`letter-spacing` は最後の文字の後ろにも空きを作るので、中央揃えには `marginRight: -tr` で打ち消す。
`paddingLeft: tr` は逆方向に動くので間違い。

### A-9 アプリ画面の再現は、縦だと文字が全滅する

Claude Code の画面をそのまま再現して縦動画に入れたら、入力欄もログも小さすぎて読めなかった。

**対処（実測値）：**
- 文字係数を **縦 1.22 / 横 0.82** に分ける（横は情報量、縦は可読性）
- タイプ中だけ入力欄へ寄る。ただし**ズームは 1.08 まで**（それ以上は入力欄の角が切れる。1.32では左のサジェストが画面外に出た）
- それでも入力コマンドは主役になれないので、**同じ文字を中央に特大で重ねる（エコー表示）**。これが決定打だった

## B. 技術の落とし穴

### B-1 Bash のヒアドキュメントで長い JS / TS を書くと壊れる

`cat > file.mjs <<'EOF' … EOF` で数百行のスクリプトを書こうとして、
`unexpected EOF while looking for matching` で失敗し、ファイルが作られなかった。
`node -e` の中でテンプレートリテラルを使ったときも、`${...}` が bash に食われて壊れた。

**対処：長いコードやテンプレートリテラルを含むコードは Write ツールで書く。**
Bash のヒアドキュメントは 30 行程度の単純なものまで。

### B-2 Node から TypeScript を直接 import できる（が拡張子が要る）

Node 22.18+ / 25 は TS の型注釈を剥がして実行できる。
これで**音声合成スクリプトが `timeline.ts` をそのまま読める**＝映像と音が同じ数字を見る。

ただし ESM の相対 import は拡張子が必須なので、そのままだと `./theme` が解決できない。
`registerHooks` で拡張子を補う（テンプレートの `make-audio.mjs` に実装済み）。

```js
import {registerHooks} from 'node:module';
registerHooks({
  resolve(spec, ctx, next) {
    if (spec.startsWith('.') && !/\.\w+$/.test(spec)) {
      try { return next(spec + '.ts', ctx); } catch { /* 次へ */ }
    }
    return next(spec, ctx);
  },
});
const {SFX, HOLDS} = await import('../src/config/timeline.ts');
```

### B-3 フォントはローカル同梱＋読み込み待ち

`@fontsource/noto-sans-jp` を npm で入れ、**日本語サブセット → ラテンサブセット**の順に import する
（後から宣言した方が重なる字形で勝つ）。`delayRender` で `document.fonts.load()` の完了を待たないと、
フォールバックのまま書き出される。テンプレートの `src/fonts.ts` に実装済み。

### B-4 Remotion 同梱の ffmpeg は「機能を削った版」

Remotion は `node_modules/@remotion/compositor-<環境>/` に ffmpeg と ffprobe を同梱している。
**これのおかげで、ffmpeg を入れていない人でも書き出しと検証ができる。**

ただし中身は削られていて、**フィルタが50個しか無い**。`tile` も `scale` も実質使えない。

| やること | 同梱のもので足りるか |
|---|---|
| MP4 の仕様を読む（ffprobe） | ○ |
| 音声を WAV に取り出す（音量の確認） | ○ `-f wav` を指定する。`-f s16le` は muxer が無くて失敗する |
| 静止画を並べて一覧画像にする | **×**（`tile` が無い） |
| 映像の加工全般 | **×** |

**対処：一覧画像は ffmpeg でなく Remotion 自身で組む。**
`src/ContactSheet.tsx` がそれ。CSS グリッドで並べて `renderStill` するだけなので
ffmpeg が要らず、おまけに各コマにフレーム番号を焼き込める。

このとき**コマの画像は `bundle()` する前に `public/` に置く**こと。
Remotion は bundle した時点の `public/` を固定するので、後から置いたファイルは 404 になる。
（コマを撮ってから一覧を組むので、**バンドルを2回**する必要がある。）

### B-5 ffmpeg の `tile` フィルタは連番読み込みで詰まる

コンタクトシートを `-i p%02d.png -vf tile=3x4` で作ったら、1枚しか読まれず残りが黒くなった。

**対処：入力を全部 `-i` で並べて `xstack` を使う。**
いまのテンプレートは一覧画像を Remotion で組んでいる（→ B-4）ので `tile` は使っていない。
**自分で任意の画像を ffmpeg で並べたくなったときは、`tile` ではなく `xstack` にすること。**

```bash
ffmpeg -y -i a.png -i b.png -i c.png -filter_complex "[0][1][2]xstack=inputs=3:layout=0_0|w0_0|w0+w1_0[v]" -map "[v]" -frames:v 1 sheet.png
```

`scale` してから `pad` するときは、pad のサイズが scale 後より小さいとエラーになる。
`scale=W:H:force_original_aspect_ratio=decrease,pad=W:H:-1:-1` の形にする。

### B-6 Playwright は入っている Chromium を直接指す

`playwright-core` を入れて、既に `%LOCALAPPDATA%\ms-playwright` にある Chromium を
`executablePath` で指定する。バージョン照合を通らないので確実。

ただし**ブラウザの場所は人によって違う**（Playwright のキャッシュ / ふだん使いの Chrome / Edge）。
パスを直書きすると自分の環境でしか動かない。テンプレートの `scripts/find-chrome.mjs` が
上から順に探すようにしてあるので、それを使う。

```js
import {findChrome} from './find-chrome.mjs';
await chromium.launch({executablePath: findChrome()});
```

Remotion 内蔵のブラウザ（`openBrowser`）はページのスクリーンショット API を公開していないので使えない。

### B-7 画面の切り抜きは縦横比を知らないと置けない

`<Img width="100%">` だけだと、コンテナの高さが決まらず潰れる。
**PNG の IHDR から実寸を読んで、目録（`assets.ts`）に `w` / `h` を持たせる。**
`gen-assets.mjs` がやっている。これがあると `crop` で「上から何割」も切れる。

### B-8 文字で要素を探すと、見えない `<script>` を掴む

「フェーズ1 自分を定義し、点を打つ」という見出しを文字で探したら、**4つとも見つからなかった。**
調べたら、`textContent.includes()` に一致した最後の要素が **`<script>` タグ**だった。

Next.js などは、画面に出しているのと同じ文字を `<script>` の中に JSON で持っている。
その要素は幅も高さも 0 なので、親をたどっても `<body>`（1440×900）まで行ってしまい、
「収まる祖先が無い」＝見つからない、で終わる。

**対処：文字で要素を探すときは、必ず「見えているもの」だけに絞る。**

```js
const hidden = /^(SCRIPT|STYLE|NOSCRIPT|TEMPLATE|META|LINK|HEAD|TITLE)$/;
const hits = [...document.querySelectorAll('*')].filter((e) => {
  if (hidden.test(e.tagName)) return false;
  if (!(e.textContent || '').includes(t)) return false;
  const r = e.getBoundingClientRect();
  return r.width > 0 && r.height > 0;   // ← これが無いと <script> を掴む
});
```

テンプレートの `capture-site.mjs` には入れてある。
**自分で新しく DOM 検索を書くときは、毎回この絞り込みを入れる。**

### B-9 画面の下にある要素は、先にスクロールしないと撮れない

ページ下部のセクションを撮ろうとして、`clip` の `y` が画面の高さを超えて失敗した。
遅延読み込み対策のスクロール（下まで行って上に戻る）では、位置は先頭に戻っている。

**対処：撮る直前に、目的の要素を画面内に入れる。**
`capture.config.mjs` の `scrollTo`（文字を指定）でやる。
`type: 'text'` は、測った位置が画面外だったら自動でスクロールしてから測り直す。

### B-10 未使用コードを置き去りにしない

`height` を destructure したのに使わず、型エラーを消すために
`<AbsoluteFill style={{display:'none'}}>{height}</AbsoluteFill>` を書いた。これはゴミ。
使わなくなった変数は destructure から外す。

### B-11 実画面のスクショを動画素材にしない

画面を見せる動画で、スクショをそのまま貼ると全部詰む。
ズーム・タイプ・カーソルは「動き」なので静止画では作れず、個人情報や実プロジェクト名が写り、
拡大すると粗く、縦横で2回撮り直しになる。

**対処：UIはコードで再現し、スクショは「見た目の正解」の参照にだけ使う。**
色・余白・文言をスクショから採取して、コンポーネントとして組む。
再現なら文字は常にシャープで、縦は「サイドバーを畳んだ1カラム」として自然にレスポンシブできる。

### B-12 自分自身を映す動画は Peek（Freeze＋Sequence）で作る

「出力された動画カードのポスター」「検品グリッド」「クリックすると再生される入れ子の映像」を
全部本物にしたい。事前レンダリングして画像を差し込むと2パスになり、変更のたびにズレる。

**対処：`<Freeze frame={g}><Sequence from={cutFrom}>...` で本編の任意フレームをその場に描く**


```tsx
<Freeze frame={g}>
  <Sequence from={cut(id).from} durationInFrames={cut(id).durationInFrames}>
    <そのシーン />
  </Sequence>
</Freeze>
```

1シーン直すとポスターも入れ子も自動で追従する。
**再帰ガード必須**：自分より後のカットは覗けない上限を入れる（入れないと自分の中に自分が出て無限になる）。

### B-13 タイプ演出は打鍵とカメラと音を1つの表から出す

`TYPE_START` と `TYPE_STEP`（3fに1文字）を timeline.ts に置き、
入力欄の文字数・中央のエコー表示・キータイプ音14発が全部同じ式を読む。
どれかを手で合わせようとするとズレる。

## C. 構成・演出の学び

### C-1 実物の画面を入れると別物になる

v1（文字だけ）と v2（実物の画面・ロゴ・サムネ入り）を同じ構成・同じテンポで作って比べた。
**v2 が圧倒的に良かった。** 同じ言葉でも「本当にあるサービス」に見える。

**URL がある案件では、実物を使う前提で設計する。**

### C-2 数字と実物の枚数を同期させると、量が伝わる

v1：数字が 0→42 にカウントアップするだけ。
v2：**サムネ 42 枚が 1 フレームに 1 枚ずつ埋まり、カウンターは「埋まった枚数」を表示する。**

数字が1増える＝コースが1枚増える、が画で一致する。
並び順をサイトのとおりにしたので、埋まるにつれて色味がフェーズごとに移り変わるおまけも付いた。

テンプレートでは `GRID.count = THUMBS.length` にしてあり、
`COPY.c7.value` とズレていたら**起動時に例外で落ちる**。

### C-3 言葉の裏づけを実物で置く

「1枚、残る。」の横に、サイトの実物の
**「このコースを終えると ／ 3か月で鍛えること3つの計画が、1枚残る」**を置いた。
言葉とサイトの文言が一字一句一致しているのが、そのまま説得力になる。

ベネフィットを書くときは、**先にサイトの中でその根拠になっている場所を探す**。
根拠が見つからない言葉は、そもそも動画に出さない方がいい。

### C-4 抽象的なパネルより実物の見出し

v1 の「4段階で、順番に。」は無地のパネル4枚だった。
v2 は**実物のフェーズ見出し4枚**（自分を定義し、点を打つ／知性の基礎を再構築する／…）に差し替えた。
箱が4つ並ぶより、実際の段階の名前が読める方が中身が伝わる。

### C-5 短く言い切る方が強い

「作れるようになる。」（9字）は縦画面に収まらず、縮めると3連の着地に見えなかった。
**「作れる。」（4字）と言い切り、落ちた情報を注釈「最後は、自分の手で。」で補った。**
結果として3連の最後が一番大きくなり、着地がはっきりした。

**入らないから縮める、ではなく、入る長さに言い換える。**

### C-6 前のカットの痕跡を「間」に残す

「間」を完全な黒にせず、直前のカットの要素を不透明度 14〜16% で残して動かさないと、
止まっていることがはっきり伝わる。テンプレートの `Hold` がこれ。

### C-7 帯やベタ塗りは、中身がないなら細くする

高速カットの背景輝度を固定するために画面下 30% にオレンジの帯を敷いたが、
実物の画面を置くようになったら、**ただの巨大な空白**になった。9% に下げた。

### C-8 背景に敷く実物は 5% を超えない

CTA の背景にホーム画面を 6% で敷いたら、文字が読めてロゴと競合した。
**3〜4% まで。**それ以上はテクスチャではなく「絵」になる。

### C-9 キャラは「合成」より「1枚のイラスト」

夜の部屋でキャラがPCに向かう画を、最初は「描いたモニターの背面＋キャラ画像」の合成で作った。
成立はするが、絵の一体感が出ない。依頼主が**ノートPCに向かうポーズの1枚イラスト**
（PC・マグ・本まで込み）を出してくれたら、差し替えただけで画が決まった。

**キャラ入りの引き画が要るときは、先に「その姿勢の1枚」を依頼主に頼む。**
ライティング（画面光のリム）とズームの目的地（絵の中のPC画面の位置）を
イラスト内の座標比で持てば、差し替えにも数分で追従できる。

## D. チェックのやり方

### D-1 コンタクトシートで一覧して見る

1枚ずつ見ると見落とす。`make-contactsheet.mjs` で

- `--set=key` … 各カットの80%地点 / 着地フレーム / 効果音の山 / 全体の0・25・50・75・100%
- `--set=fast` … 高速カットを1コマずつ
- `--frames=210,225,240 --scale=0.45` … 怪しい箇所を拡大

**縦と横の両方を見る。** 横は必ず別の問題が出る。

### D-2 コンタクトシートの見え方に騙されない

縮小された一覧では「切れている」ように見えても、実はマスクの途中だったことが何度もあった。
**怪しいと思ったら `--frames` で拡大して確かめる。**推測で直すと別の場所が壊れる。

### D-3 最後は MP4 から直接フレームを抜く

静止画チェックは Remotion のプレビュー経由。**書き出した MP4 で確認するまでは「未確認」。**

```bash
ffmpeg -i output/final-vertical.mp4 -vf "select='eq(n\,6)+eq(n\,213)',scale=300:-1,tile=2x1" -frames:v 1 check.png
```

### D-4 音は数字で確かめる

耳で聴けないので、必ず測る。

```bash
ffmpeg -i out.mp4 -af "loudnorm=print_format=summary" -f null - 2>&1 | grep -E "True Peak|Integrated"
```

「間」が本当に止まっているかも、区間を切って測れば分かる。

```bash
ffmpeg -ss 2.0 -t 0.5 -i out.mp4 -af volumedetect -f null - 2>&1 | grep max_volume
```

実測例：間の中 -57 dB／直後 -2 dB。ちゃんと止まっていた。
